# 网络语境：懂梗，但不硬玩梗

这个模块不是热词词典。它帮助 Agent 判断一个表达在当前上下文里是什么意思、对谁说、要不要接，以及能不能主动使用。

## 两条路线

### 输入理解

- 用户本轮给出的解释是当前语境的强证据，但不自动变成全网通义。
- 表达可能多义时，结合前后文、对象、说话方向和关系判断。
- 证据不足且含义会影响答案时，索要一句前后文；不影响任务时保留不确定性并继续。
- 不编造来源、年份、流行度或圈层。

### Agent 输出

- `understand_only`：可以理解和解释，不能因为看到条目就主动使用。
- `echo_allowed`：用户已经在当前低风险语境使用，可自然跟随，但不能换对象或扩大含义。
- `proactive_allowed`：只有独立核验了语境、方向、关系和时效后才可主动使用。

首发种子全部是 `understand_only`。没有合格候选时，直接说自然中文。

## 数据字段

种子文件使用独立字段：

- `term`、`aliases`：表达及识别变体；
- `type`：表达类型；
- `meaning`：当前可支持的简短理解；
- `signals`：需要结合判断的上下文信号；
- `good_when`、`avoid_when`：适用和不适用条件；
- `active_use`：输出权限；
- `confidence`：当前置信度；
- `examples`：独立撰写的短例子，不代表真实聊天样本。

## 与 CHIME 的关系

字段和评测设计参考了 CHIME 的六类划分：现象、引用、修辞、谐音、俗语、缩写。CHIME 的研究表明，模型对引用梗、谐音梗和来源尤其容易出错。

本项目不打包或再分发 CHIME 数据，也不把 CHIME 条目当作当前热度或主动输出白名单。用户如果单独取得 CHIME，只能把它作为外部理解评测源；其数据仍受原项目许可证和用途说明约束。

参考：

- CHIME repository: https://github.com/yuboxie/chime
- EMNLP 2025 paper: https://aclanthology.org/2025.emnlp-main.863/

## 用户教学与贡献

新增表达先进入 `understand_only`。最小贡献内容包括：表达、含义、脱敏前后文、说话方向、适合与不适合的语境，以及是否允许 Agent 主动使用。

一条反馈只能更新对应表达。不要自动扩展相邻词、批量生成类似梗，或把投票数量当成真实性和当前流行度证明。
