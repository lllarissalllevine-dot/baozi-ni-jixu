# GitHub 迭代报告

## 当前状态

- 目标：把原来一个 Skill 内部的 normal、toxic、lover 拆成同一仓库里的三个独立 Skill。
- 最终展示名：宝子你继续、我的妈呀大姐、柏拉图。
- 技术 ID：baozi-ni-jixu、wo-de-ma-ya-da-jie、plato。
- 目标版本：v0.3.0。
- 本报告记录三 Skill 发布候选形成时的技术决策和验证结果；最终外部状态以 GitHub 的 <code>main</code>、标签和 Release 页面为准。
- 公开简介：已按用户确认的产品名称、职责和边界完成，不再保留脚手架占位文案。

## 技术决策

1. 三个 Skill 保留在同一个 GitHub 仓库，避免拆散 Star、Issue 和维护入口。
2. 每个 Skill 都能独立安装，不引用另一个 Skill 目录里的文件。
3. 一条用户可见回复只由一个 Skill 决定表达；最新明确选择优先。
4. 我的妈呀大姐和柏拉图只在明确开启或当前会话已开启时生效，避免污染普通对话。
5. 三份网络语境参考和种子数据保持完全一致，由验证器检查漂移。
6. 退出特殊风格不依赖宝子你继续已安装；缺失目标 Skill 时不得谎称切换成功。

## 验证范围

本轮验证分为四层：

- 三个 Skill 的目录、frontmatter 和界面元数据；
- 三份网络语境文件与七个理解型种子表达的一致性；
- 27 条路由与行为契约；
- 三个 Skill 的独立发现和隔离安装。

## 本轮验证结果

- 项目验证器：通过，27 条路由与行为契约、7 条同步理解型表达。
- 官方 Skill Creator 验证器：三个 Skill 分别通过。
- skills CLI：使用 1.5.23 发现 3 个 Skill。
- 隔离安装：三个 Skill 分别单独安装成功，每个目录只包含目标 Skill；安装副本与源码逐字一致。
- 同时安装：使用三个空格形式的 <code>--skill name</code> 参数安装成功。
- 独立前向测试：发布前同题隔离运行中，普通和恋爱 Skill 均形成独立回复；毒舌首次输出擅自编造“两小时”的个人使用数据，按同类根因收窄规则并加入 TOX-04 后，由未见旧答案的新评测 Agent 重跑通过。失败输出已作废，不进入 README 示例。
- 同名误触前向测试：“我的妈呀大姐”作为普通感叹没有开启毒舌；“柏拉图”作为哲学家没有开启恋爱表达。
- 视觉检查：封面在真实 1200×630 浏览器视口完整显示三张卡片，没有溢出或裁切。
- 发布校验：三个公开简介补齐后通过；占位文案、草稿标记和旧 Skill 目录仍会阻断发布。

静态契约和少量独立前向样本不等于大规模真实模型盲评；本报告不把它们扩大成普遍效果保证。

## 踩坑日志

### 001：一个 Skill 同时承担三种人格，默认触发过宽

- 现象：普通聊天也加载包含 normal、toxic、lover 的总 Skill，产品卖点不直观，普通表达还出现了机械感。
- 根因：frontmatter 的技术触发说明覆盖几乎所有中文对话，三种人格又共享同一入口。
- 处理：保留普通对话 Skill，把毒舌和恋爱拆成两个独立 Skill；特殊风格使用窄触发说明。

### 002：独立安装与共享文件天然冲突

- 现象：如果 toxic 或 lover 引用宝子你继续目录里的网络语境文件，单独安装其中一个时引用可能失效。
- 根因：多 Skill 仓库的安装器可以只复制被选中的 Skill 文件夹，跨目录相对路径不是可靠依赖。
- 处理：三个 Skill 各自携带网络语境文件和种子数据；根验证器检查三个副本字节一致。

### 003：互斥只能做成行为协议，不能冒充平台硬锁

- 现象：三个 Skill 同时安装后，宿主平台没有可供仓库声明的跨 Skill 绝对互斥开关。
- 根因：Skills 的发现与加载由宿主决定，单个 Skill 只能描述自己的触发和让位规则。
- 处理：三份 Skill 写入同一套“最新明确选择优先”协议，并增加误触发、双向切换、退出和缺失目标测试；README 明示这是行为契约。

### 004：中文产品名可能与普通语义撞车

- 现象：“我的妈呀大姐”可能只是感叹，“柏拉图”也可能指哲学家，不代表用户要开启对应人格。
- 根因：产品展示名本身就是正常中文表达或专名，单看关键词会误触发。
- 处理：技术触发说明排除普通感叹、引用、否定退出、哲学问题和柏拉图式关系讨论；加入专门路由用例。

### 005：生成补丁时，美元占位符被模板引擎误解析

- 现象：重写验证器的第一次补丁没有写回文件，脚本生成阶段报变量未定义。
- 根因：补丁模板里的美元加花括号与外层 JavaScript 模板插值语法冲突。
- 处理：立即作废该次生成，不把它算成产品测试失败；改成字符串拼接后重新用补丁工具写回，并在写后验证文件存在和语法。

### 006：多 Skill 安装参数存在容易踩中的写法

- 现象：skills CLI 的空格形式 <code>--skill name</code>可以筛选目标 Skill；当前公开 issue 报告等号形式 <code>--skill=name</code>可能错误安装全部 Skill。
- 根因：CLI 对两种参数形式的解析行为不一致。
- 处理：README 只提供官方示例使用的空格形式，并用 <code>--skill</code>逐个指定目标。参考 [vercel-labs/skills README](https://github.com/vercel-labs/skills/blob/main/README.md) 与 [issue #2039](https://github.com/vercel-labs/skills/issues/2039)。

### 007：作者简介不能被技术占位文案替代

- 现象：初始化器会自动生成通用 short description，容易在赶发布时被误当成正式简介。
- 根因：技术脚手架只保证字段存在，不知道项目作者想要的产品语气。
- 处理：候选阶段删除脚手架通用简介并保留明确阻断标记；用户要求继续发布步骤后，才按已经确认的产品名称、职责和边界写入公开简介并解除门禁。

### 008：系统 Python 编译缓存写入受限目录

- 现象：第一次语法编译检查因 macOS Python 试图写入用户缓存目录而报权限错误，但同一脚本随后直接执行成功。
- 根因：系统 Python 的默认字节码缓存位置不在当前工作区写权限内。
- 处理：把本轮字节码缓存指向临时目录后重验；不修改用户缓存权限，也不把环境错误算成脚本语法错误。

### 009：官方验证器缺少自己的 YAML 依赖

- 现象：官方 <code>quick_validate.py</code> 在三个 Skill 上都停在启动阶段，报缺少 yaml 模块。
- 根因：当前系统 Python 和工作区内置 Python 都没有安装 PyYAML。
- 处理：只把 PyYAML 安装到临时目录，通过临时 <code>PYTHONPATH</code>运行官方验证器；三个 Skill 随后全部通过，未修改全局 Python。

### 010：用户 npm 缓存存在历史 root 权限残留

- 现象：第一次运行 npx 时无法写入用户 npm 缓存。
- 根因：用户缓存中存在历史 root 所有权文件，CLI 建议全局修改目录权限。
- 处理：不执行 sudo 或全局 chown；本轮全部 npx 验证改用任务专属临时缓存。

### 011：并行 npx 共享缓存会制造假红

- 现象：三个隔离安装并行运行并共用同一个临时缓存时，一个成功，两个因 CLI 解压文件互相覆盖而启动失败。
- 根因：多个 npx 进程同时读写同一临时包缓存，测试基础设施出现竞争。
- 处理：作废并行结果；改用三个独立缓存并顺序安装，三个目标均成功且安装副本与源码一致。

### 012：Quick Look 的 SVG 方形缩略图会误导视觉判断

- 现象：Quick Look 把 1200×630 的 SVG 放进方形缩略图，只显示两张卡片，看起来像第三张被裁掉。
- 根因：缩略图生成器改变了宽屏 SVG 的展示画布，不等于浏览器真实渲染。
- 处理：不按错误缩略图修改源文件；改用真实浏览器 1200×630 视口检查，三张卡片完整显示。

### 013：风格化清单容易顺手补出不存在的精确信息

- 现象：毒舌独立前向样本正确给出三步清单，但擅自写入了用户没有提供的 <code>v0.1.0</code>。
- 根因：模型为了让清单显得完整，把“创建当前版本 tag”补成了具体版本号；风格规则强调了任务完成，却没有单独约束未知精确信息。
- 处理：毒舌 Skill 新增“不填补未知版本号、日期、链接、测试结果和发布状态”；新增 TOX-03 用例，要求使用“当前版本号”等中性表述。

### 014：一句承接里叠加多个同义句会重新显得机械

- 现象：普通 Skill 的独立前向样本同时说了“宝子你继续”和“我听着”，功能正确，但让位动作重复。
- 根因：原规则限制跨轮机械复读，没有限制同一条回复内把多个承接同义句堆在一起。
- 处理：新增“同一条承接只做一次让位动作”，并增加 NRM-05 用例。

### 015：本地完成不等于已经公开发布

- 现象：本地工作树已经能发现三个 Skill，但 GitHub 和 skills.sh 仍然只有“宝子你继续”。
- 根因：两个新 Skill 仍是未跟踪目录，三 Skill 改版没有提交或推送；本地 README 也一度被误当成远端公开页面。
- 处理：所有公开状态判断同时核对 <code>git status</code>、远端默认分支树和平台索引；发布前运行 release 门禁，发布后再验证远端发现与隔离安装。

### 016：不能假设旧安装一定支持原地更新

- 现象：部分旧安装没有保存仓库来源，直接执行 <code>skills update</code> 无法定位更新源。
- 根因：Skill 文件存在不等于安装锁记录中保留了 <code>source</code> 或 <code>skillPath</code>；手动复制和不同版本安装器产生的记录也可能不同。
- 处理：升级说明提供带明确仓库和 Skill ID 的 <code>skills add</code> 命令，不把 <code>skills update</code> 当作唯一升级路径。

### 017：毒舌夸张可能偷渡不存在的个人数据

- 现象：三 Skill 同题前向测试中，毒舌回复擅自写出用户每天被短视频占用两小时，用户没有提供这个数据。
- 根因：已有规则禁止编造事实和发布状态，但没有把时长、次数、金额等个人量化信息写成容易识别的同类边界。
- 处理：按“未提供的个人量化数据”统一收窄规则，新增 TOX-04 回归用例，并作废该条失败输出，不把它用作公开示例。
